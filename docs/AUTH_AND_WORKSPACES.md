# 账户、工作区与设备会话

SuperSophie 使用“账户名 + 高熵访问密钥”登录。访问密钥仅在用户设备输入；服务端保存 PBKDF2-HMAC-SHA256 派生值和随机盐，不保存明文。整个注册、登录、会话和工作区授权链路均由 SuperSophie 自己提供，不读取 ChatGPT/OpenAI 账户、认证头或 OAuth 会话。

托管入口允许匿名访问注册/登录页；登录后的所有数据接口仍必须通过 SuperSophie 的 HttpOnly 会话和工作区成员校验。公开入口不等于公开数据。

## 安全模型

- 访问密钥使用 Cloudflare Workers Web Crypto 支持上限内的 100,000 次 PBKDF2-HMAC-SHA256；访问密钥本身由 32 字节安全随机数生成，不依赖人类口令提供熵。不存在的账户也执行等量派生工作，降低时序枚举。
- 会话令牌为 256 位随机值，D1 只保存 SHA-256 哈希。
- Cookie 使用 `HttpOnly`、`SameSite=Strict`；HTTPS 使用 `Secure` 与 `__Host-` 前缀。
- 所有写操作校验同源请求，业务 API 在服务端校验工作区成员和写权限。
- 登录失败按账户名与来源地址的哈希限流；错误消息不暴露账户是否存在。
- 公开注册按来源地址限制每日可创建的账户数，降低自动化滥用。
- 密钥轮换要求当前密钥，并撤销其他设备会话。用户也可单独撤销某台设备。
- 账户菜单可在本机生成并复制新的高熵访问密钥；只有用户输入当前密钥并确认轮换后才会生效，助手和管理员都不能读回或代替用户恢复明文。
- 登录、退出、轮换、撤销等事件以 Markdown 写入 `security_events`，其中不含密钥或会话令牌。

## 工作区隔离

每个会话有一个活动工作区。页面、对话、Agent、数据源、代码项目、连接器、同步事件和 R2 资源都由 `workspace_id` 或受验证的父级资源归属工作区。客户端提供的逻辑 ID 会在服务端加工作区前缀；API 返回时再移除前缀，避免两个工作区使用同一页面 ID 时互相覆盖。

第一个注册账户会接管开发期的 `default` 工作区，以保留已有本地数据。之后创建的账户和工作区使用随机 ID，不共享旧数据。

## 当前边界

- 没有邮箱找回流程；丢失访问密钥时无法绕过验证恢复账户。
- 工作区成员表已经支持角色，但当前界面只创建 owner 工作区，邀请与细粒度协作权限仍待实现。
- 若使用私有企业部署，可在 SuperSophie 账户层之外再叠加发布平台访问策略；普通公开部署不需要 ChatGPT 登录。
